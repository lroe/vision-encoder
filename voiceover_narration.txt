A picture is a grid of pixels. Each pixel is three numbers: red, green, blue. Even a small two hundred twenty-four by two hundred twenty-four photo has over fifty thousand pixels. Far too many to feed in one by one.

Each square holds fourteen times fourteen pixels, with three colors each. That's five hundred eighty-eight numbers.

Now push each square through one simple multiplication, so it comes out as a vector the same size as a text vector. Done. You have two hundred fifty-six image tokens. Put them in front of the text, and the language model reads them like words.

So the question is about the room. Does the desk have to sit in a separate room? Or can it sit inside the main office?

Quick reminder of what happens inside a language model. It's a stack of layers. In each layer, tokens first look at each other. That step is called attention. Then each token gets processed on its own by a small network, the feed-forward network, or F F N. In every layer, text tokens and image tokens go through the same weights.

Here's their trick. Remember the expert's desk? Instead of a separate room, put the desk inside the main office. In a few layers, add a second set of weights, a desk that only image tokens sit at. For an image token, the layer's output is the shared output, plus the output of this extra desk. For a text token, the desk is switched off.

One extra term, with a light switch. M is the switch: one for image tokens, zero for text. The extra desk starts empty, set to zero, so at step one the model behaves exactly like the plain one. And text-only inputs get processed exactly as before. The full version also adds a vision-only desk to the attention step, but the idea is the same.

They call it in-fusion. The desk moves out of the separate room and into the main office. No separate network in front. Extra capacity, inside the model. Before you go delete SigLIP from your repo, you need to hear what this paper does not say.

One. Their pretrained encoders only saw the same images as everything else. A released encoder trained on far more data might still help. The authors say their results don't rule that out.

Two. These are dense models, up to six point four billion parameters. Dense means every token uses all the weights. Mixture-of-experts, where each token only visits a few specialist sub-networks, is untested.

Three. Training images are small, two hundred twenty-four by two hundred twenty-four. Higher resolution and text-heavy data are left for later.

Four. The data mix was tuned on the from-scratch encoder at one point seven billion. Mixes tuned for each recipe are still open.

So if you're fine-tuning a released model with SigLIP inside, nothing here tells you to rip it out.

But if you're designing a model, this gives you four rules.

If you train a vision-language model end to end, stop budgeting for a separate encoder pretraining stage, and start images from the first update.

If you want to drop the encoder, don't just delete it. Take its parameter budget and spend it as vision-only weights in the first layers.

If you compare vision encoders, don't trust recognition scores to predict how well a model answers questions. Test on reading text, charts, and the tasks you care about.

And if you serve images, measure time to first token with your own mix of requests.

The authors' own conclusion is to train these models end to end, as one system, instead of gluing together parts built for different goals.
